## Findings

1. **README claims corrected.** Three claims the code contradicted, fixed in
   this pass:
   - The gallery frames were described as 1600x900; the shipped PNGs in
     `docs/shots/gallery/` are 1000x563.
   - The Cyber-Pass probe stamp was described with a `P95` field; the stamp
     prints `ENG engine · Q queue`, and p95 was moved off the booth
     (`web-react/src/scenes/cyber-pass/AssayPlate.jsx`).
   - The Deepsignal `RUNTIME` span was described with `tps TOK/S` and `tempC`;
     the span prints `model · ENG engine · candidates`, and throughput and
     thermals are deliberately excluded
     (`web-react/src/scenes/deepsignal/EdgeBars.jsx`).
   - The test count in the README was stale (`115` vs the current suite).

2. **Latent bug in the reasoning adapter (fixed).** `reasoning.MTP_RE` used
   `(\d+)`, so a comma-grouped total (`mtp accepted 772/1,024`) captured only
   `1` and produced a nonsense accept percentage. `THINK_RE` in the same
   module and `speculum.py` both already accept commas. The pattern now
   accepts them. The path had no test coverage; a test was added.

3. **Adapter path had no coverage (tests added).** `router.py`,
   `reasoning.py` and the `aether.snapshot()`/`tick()` merge were untested.
   Three tests now cover the merge, the router bounds and run-folder scan, and
   the reasoning parse/dedupe/bounds.

4. **One environment-dependent test failure.** On a host running a supervisor
   wrapper process whose argv names an engine binary, the wrapper has an RSS
   below the 0.01 GB reporting precision and rounds to `0.0`;
   `collector/test_hostinfo.py::TestLinuxBackend::test_processes_shape` then
   fails its `rss_gb > 0` assertion. This is host state, not a repo regression:
   the suite is green without such a process. Left unchanged on purpose — the
   fix would weaken a real invariant for one launcher shape. Worth a separate
   decision (relax the invariant, or have `hostinfo.processes()` report a
   sub-precision RSS as `None`).

5. **A transient engine-test failure was observed once** in
   `collector/test_engines.py::TestLlamaCppPoll::test_schema_and_rates` during
   a full run; it did not reproduce in four later runs and passes in
   isolation. Recorded here as a flake to watch.

6. **No lint is configured.** Neither `README.md` nor `web-react/package.json`
   documents a lint step, and there is no eslint/prettier/ruff/flake8 config in
   the tree, so there is nothing to run as "documented lint". `pyflakes` (not
   part of the repo) reports 9 pre-existing unused imports/variables in
   `collector/`; none are touched here.
